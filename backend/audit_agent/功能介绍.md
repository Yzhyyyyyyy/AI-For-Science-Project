# 审计 Agent (Audit Agent) 接口与数据规范

本模块作为系统的“质检中枢”，位于五维评价模块与全局统筹模块 (`main.py`) 之间。其核心职责是对成功返回的初步评价结果进行清洗和纠偏。

## 1. 核心审查维度

审计 Agent 主要针对以下两个维度进行自动化审查：

1. **幻觉与“假证据”校验 (Fact-Checking)**
   * **审查内容**：核对成功评价维度给出的 `evidence`（如特定的图表号、数据值、段落引用）是否在原始论文中真实存在。
   * **处理方式**：若发现评价 Agent 捏造了不存在的证据（大模型幻觉），审计 Agent 将在结果中剔除该伪证，并修正相关评价。

2. **跨引擎冲突仲裁 (Conflict Resolution)**
   * **审查内容**：检查五个评价维度之间是否存在严重的逻辑矛盾或极大的分数差异（例如：创新评价给出高分，但逻辑评价指出致命推导错误）。
   * **处理方式**：基于原始论文进行二次推演，判定哪一方的评价更准确，并在最终输出中修正出错一方的结论。

---

## 2. 接口输入与输出声明

为了保证审计 Agent 正常工作，统筹模块 (`main.py`) 在调用时必须严格遵守以下 I/O 规范：

### 输入要求：必须同时传入双 JSON 数据
调用审计 Agent 时，必须传入包含以下两部分的 JSON 对象：
1. `original_paper`：数据处理模块解析出的【原始论文标准 JSON】（用于查证原文）。
2. `preliminary_reports`：五个评价维度中成功返回的【初步评价结果 JSON】（用于被审查）。

### 输出要求：返回单 JSON 数据
审计 Agent 处理完毕后，只会返回一个包含仲裁日志和清洗后数据的 JSON。
